## Changes the paper's harness must make

1. **Ledger permissions (v0.10.2 / main, #775).** Create or copy every SQLite ledger with mode 0600 **and its `-wal` and `-shm`**, or keep it in a 0700 directory owned by the engine user; never group/other-writable (no override exists). Same for `VTOP_AUDIT_LOG` (group read allowed) and any `manifest.mac.keys[].file`. Do not use `security.allow_loose_secret_permissions` in measured runs; `vtopctl validate` will report a refusal before a run.
2. **Fault injectors that write the ledger** must `INSERT` with `state = 'batching'` and then `UPDATE` (trigger `trg_batches_insert_as_batching`). State strings are lower-case, including `superseded`.
3. **Power-loss emulation.** Do not delete the whole WAL after SIGKILL. Record the WAL length after each FULL write (VERIFIED, SOURCE_COMMITTED, and audit appends by `replay`/`prune-ledger`/`migrate`) and truncate to the last one at or before the crash point; keep the run below the auto-checkpoint size or account for checkpoints.
4. **No-recheck ablation.** Patch `storage_still_verified` (E:3866) to return `(Recheck::Strong, <BatchCheck>)` and skip `scrub::check_stored_batch`; the return type is a 4-valued enum plus the check, not a bool.
5. **Duplicates (RQ1, Table 4).** Count objects by object URI, not by manifest. Stable keys need a checksum (`sha256`/`blake3`), the `s3_native` or `localfs` backend, and **`s3:ListBucket`** on the bucket (otherwise HEAD on a missing key is 403 → `fallback_unchecked` → per-attempt key). Parse `object_key_*` events to attribute each fallback.
6. **Store-SHA-256 cost (RQ3).** Any compressed object ≥ `upload.multipart_threshold_bytes` (8 MiB, inclusive) is multipart and verified by read-back (message "... verified by read-back (no service whole-object checksum; multipart or unchecked upload)"). Either raise the threshold above the largest object, keep objects below 8 MiB, or report the two paths separately. This was already so at v0.7.0.
7. **Kafka.** Do not delete the consumer group's committed offsets between runs while keeping the ledger: with no broker offset the engine ignores the ledger and follows `auto.offset.reset`.
8. **File-source log parsing.** Classify rotation/truncation by the read-path messages from `continuity.rs` ("file replaced (inode A -> B)", "file truncated", "file content replaced at the same inode", "file content rewritten at the same inode"), not by the `Kept` names, which belong to `delete_after_commit`.
9. **Event parsing.** Keep matching the message strings; `manifest_uploaded` and `verification_passed` now carry extra fields (`version`, `verification_class`, `object_check`, `manifest_check`) under `--json`.
10. **Size-only / weak backends.** Unchanged from v0.7.0: with the default strong policy, a backend that can only confirm size fails every batch (FAILED → replay loop); a per-stream `checksum.algorithm: none` is refused at load.
11. **`AWS_REQUEST_CHECKSUM_CALCULATION=when_required`** removes the store-side header only on BLAKE3/`none` streams; SHA-256 streams still send `x-amz-checksum-sha256`.
12. **`manifest.write_version`** must be quoted if the harness sets it.
